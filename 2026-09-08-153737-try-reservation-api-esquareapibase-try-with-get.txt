  What's broken

  I ran CalendarJS + LemonadeJS from the same CDN URLs in jsdom with that exact
  payload. The events reach the correct cells, but nothing renders. Sept 10's
  cell:

  <div data-start="false" data-end="false" data-last="false" data-range="false"

  No data-event attribute — 10 of 42 cells hold event arrays, and
  div[data-event=true] matches 0.

  Cause: CalendarJS's day template binds data-event="{{self.data}}", and
  self.data is the array of events. LemonadeJS's setter routes object/array
  values to a JS property (el['data-event'] = [...]) instead of an HTML
  attribute — only strings/booleans become attributes. So the library's own
  marker rule,
  .lm-calendar-content>div[data-event=true]::before{…background-color:red},
  never matches. The array is there (cell['data-event'] is Array(2) on the
  10th), just invisible.

  Two consequences beyond the missing dot: the 'Occupé' title is never displayed
  anywhere, and occupied days stay selectable (data-disabled="false") — a
  visitor can pick 2026-09-10 even though it's booked twice.

  Fix

  validRange accepts a function called on every render — validRange(day, month, 
  year, cell), returning true to disable. It's the supported hook, survives
  month navigation, and can set cell.bold (styled by
  div[data-bold=true]{font-weight:700}). In buildCalendar
  (ReservationForm.php:556):

  function buildCalendar(events) {
      if (!window.calendarjs || !window.calendarjs.Calendar || !calHost) {
  return; }
      var busy = {};
      events.forEach(function (e) { (busy[e.date] = busy[e.date] || []).push(e);
  });

      calendar = window.calendarjs.Calendar(calHost, {
          type: 'inline', format: 'YYYY-MM-DD', footer: false, startingDay: 1,
          data: events,
          validRange: function (d, m, y, cell) {
              var iso = y + '-' + ('0' + (m + 1)).slice(-2) + '-' + ('0' +
  d).slice(-2);
              cell.bold = !!busy[iso];          // visible marker
              return iso < todayISO();          // keep the "no past dates" rule
          },
          onchange: function (self, value) {
              if (typeof value === 'string') { toggleDate(value.substring(0,
  10)); }
          }
      });
  }

  Note validRange as a function replaces the validRange: ['2026-…'] array, so
  the past-date rule has to move into it — that's what the return line does. Add
  || !!busy[iso] to that return if booked days should also be unselectable; I
  left them selectable since your entries come back with moderate: 2 and the
  form is a request, not a confirmed booking. Your call.

  One unrelated thing I noticed: enqueueAssets (:86-88) loads @calendarjs/ce and
  lemonadejs from jsDelivr without a version in the URL while passing
  '1.1.0'/'5.3.6' as the WP version string — so you actually ship whatever
  latest is that day. Worth pinning the URLs (@calendarjs/ce@1.1.0).

  I didn't modify any files, and nothing was POSTed to the live API.
